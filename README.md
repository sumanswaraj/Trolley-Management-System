# Smart Trolley Management System

Version 0.4.0 is a runnable full-stack plant pilot with a responsive UI, authenticated Node.js API, persistent SQLite storage, configurable plant policies and a signed reader-observation interface. Code is separated into views, controllers, services, validation, security, database access and versioned migrations.

## Connected private demo

Open https://smart-trolley-demo.swarajminiscience199.chatgpt.site and sign in with the same ChatGPT account. The demo uses a persistent hosted D1 database and 24 sample trolleys. Switch sample roles in the demo toolbar to try independent approvals. It uses managed Site identity; sample actors are not real production logins. Real reader provisioning and user administration remain in the full Node installation. The hosting adapter source is included under deploy/hosted-demo.

## Run on Windows, Linux or macOS

1. Install Node.js 24 or later.
2. Copy .env.example to .env. Set a unique ADMIN_PASSWORD with at least 12 characters.
3. Run `npm ci --omit=dev --ignore-scripts` to install the pinned QR packages.
4. Run `node --env-file=.env server.mjs`. On Windows, you can double-click start-windows.cmd; it installs production dependencies if missing.
5. Open http://127.0.0.1:8080 and sign in as admin with your configured password.
6. Add locations, products (category/unit) and trolleys (capacity/unit), then create named users.
7. Configure compatibility, routes and location rights in Plant rules before enabling enforcement.

ADMIN_PASSWORD bootstraps the first account only; changing it after initial setup does not reset an existing password. Reader provisioning additionally requires DEVICE_ENCRYPTION_KEY; manual/QR workflows work without it.

## Included features and packages

- Responsive desktop navigation and phone trolley cards; fleet search and shared state.
- Named users, salted scrypt passwords, server permissions, sessions, deactivation and session revocation.
- Capacity units, trolley/product compatibility, allowed routes, quality release and location-scoped operations.
- Transactional departures, independent approvals, reasoned exceptions and physical receipt confirmation.
- Idempotent requests, version conflicts, one-open-movement protection, retained movement history and append-only audit.
- Camera QR scanning with native detection and self-hosted jsQR fallback; USB/manual IDs; QR labels generated by qrcode.
- Per-reader HMAC credentials, encrypted secrets, tag mappings, observation history, rotation/revocation and replay deduplication.
- Paged histories, complete movement CSV export and reports based on real events.
- Docker/Compose, Windows launcher, backup script, integration/browser tests, formatting checks, CI and operational documentation.

The original supplied demo is preserved as public/prototype.html for reference. It is not served by the operational app, so its simulated roles/CDN scripts cannot run within an authenticated workspace.

## Workflow

Identify a trolley, choose destination and declare the load. Policy-compliant internal departures begin immediately. Outside, quality and exception requests wait for independent approval. Operational location changes only after receipt is confirmed. Reader observations are evidence of scans and do not silently move trolleys. See docs/PLANT_POLICY.md and docs/READER_INTEGRATION.md for configuration and physical-integration boundaries.

## Validation

Run `npm ci --ignore-scripts` for development tooling, then:

    npm run check
    npm run format:check
    npm test
    npx playwright install chromium
    npm run test:browser
    npm run test:load

Browser tests support CHROMIUM_EXECUTABLE_PATH when using an existing compatible browser. See docs/VALIDATION.md for measured results and their limits.

## Deployment and recovery

Set ADMIN_PASSWORD in .env and run `docker compose up --build -d` for a local pilot. The database persists in the trolley-data volume. The supplied port is localhost-only. The additional compose.production.yaml/deploy.Caddyfile template supports HTTPS on a confirmed DNS hostname. Follow docs/OPERATIONS.md for deployment, monitoring, backups and restore drills. Back up the reader wrapping key separately from the database.

This release remains single-instance SQLite software. PostgreSQL/HA, managed SSO/MFA/password recovery, durable offline device queues, physical RFID drivers and production rollout require further implementation/validation. No enterprise SLA is claimed. See docs/ARCHITECTURE.md, docs/API.md and IMPLEMENTATION_PLAN.md for the remaining release work.
